# CreatorPulse Local Bridge
No dependencies beyond Python 3.10+ standard library. Runs on the always-on Hermes host. Keep it in a dedicated OS account/service if possible, separate from the agent shell; do not allow Hermes to read the bridge token or DB files. On Windows use a separate restricted account and NTFS permissions (Unix umask does not provide equivalent ACLs).
## Agent-led setup and recovery
For Sandbox, start with [the repository runbook](../integrations/hermes/SANDBOX_RUNBOOK.md). Hermes performs safe inspection, preparation and read-only verification; owner-only secret handling and elevated execution remain separate. The Windows preflight and reviewed startup helper are linked there. Do not regenerate existing keys or recopy a live database.
## Setup
From repository root, run `python local-bridge/setup.py --environment sandbox`. This creates ignored, private local configuration files, using cryptographically random credentials. It does not configure Vercel, start a tunnel or connect TikTok. Do not put generated secrets in chat, Git, model memory, or logs. Store operator key in a password manager. Transfer the agent key only to the Hermes MCP credential configuration; the bridge/vault/operator keys must not be available to the model.
Run `python local-bridge/run.py --environment sandbox` to start the bridge. Sandbox: 127.0.0.1:8766, data/sandbox/creatorpulse.sqlite3. Production: --environment production, port 8765, data/production/creatorpulse.sqlite3. Each environment generates separate role-prefixed keys in .secrets/<environment>/. Legacy secrets/database must not be silently migrated. Use systemd, a Windows service or equivalent supervisor for continuous operation. Provide an HTTPS reverse proxy/tunnel to exactly /storage/v1; use a stable URL, not an unauthenticated public HTTP listener. The bridge additionally verifies a high-entropy bearer credential. Set request-body limits and rate limits on the proxy. Do not expose the SQLite file or any other port. No tunnel provider is selected or provisioned.
## Vercel
In the existing project, add the five server-only entries from local-bridge/.secrets/sandbox/vercel.env (Preview, branch sandbox only; Production uses its own .secrets/production/vercel.env). The bridge URL must be https://YOUR-HOST/storage/v1. Do not replace existing TikTok credentials, APP_URL or redirect URI. Redeploy only after the intended release is accepted; confirm the production domain serves its commit. Without the five entries the gateway stays disabled. The generated file contains secret values; keep it private. Retain the encryption key across deployments or existing encrypted records become unreadable.
## Enroll
Open the canonical dashboard for the selected environment and log into each desired TikTok account as usual. In V4 baseline, open Accounts to connect accounts, then AI Agent, select Account for enrollment, enter operator key and explicitly enroll the active account (maximum three). In V3 production, use the existing account switcher and AI Agent integration panel. Repeat for each account. Browser-only and gateway enrollment are distinct. Then connect Hermes using integrations/hermes. Check list_accounts and analytics through the actual Hermes adapter; public gateway health only indicates config completeness, not Bridge reachability. Removing a browser session or logging out does not delete the persistent gateway record; operator can disconnect it via the API. Revoking TikTok authorization is separate.
## Health and backup
Test using the bridge bearer key with POST /storage/v1 and JSON ["PING"]; expected {"result":"PONG"}. Never include the secret in command history. The bridge has no generic SQL or Lua executor: the command-shaped protocol accepts only fixed operations. SQLite WAL persists data across restarts. Use SQLite online backup or stop the bridge and back up the complete database; never copy only the main file while writes are active. Keep encrypted backups and vault key separately. Host/tunnel outage disables enrolled account operations. Do not retry uncertain publications.
Run tests: `python -m unittest discover -s local-bridge -p "test_*.py"`.

Sandbox domain: https://creatorpulse-studio-git-sandbox-total-management1.vercel.app. Production domain: https://creatorpulse-studio-six.vercel.app. Use two distinct HTTPS tunnel routes, each mapping to its environment's loopback port. Never share a vault key, bridge token, operator key, agent key or database across environments. Scope Vercel Preview secrets specifically to sandbox; do not expose them to unrelated branches. Secret generation and privileged service setup are owner-only; safe preflight, preparation and read-only MCP verification are agent tasks. Preserve any legacy database and vault keys for explicit migration.

## Central manual publication history (Sandbox)
The Bridge now has an additive manual_publications table keyed by verified TikTok account slot and request ID. It records the submission before the upstream call, saves publish_id before upload, and updates status from TikTok reads. It displays the latest 200 records per readable account; no automatic deletion. Browser copies are imported only after successful TikTok status verification with that account's token and retained locally if unavailable. No reposting during import. New manual publishing is blocked before submission while a configured Bridge lacks the history protocol. Existing PC09: use the reviewed self-contained integrations/hermes/windows-owner-history.ps1 through the resume controller's OWNER_HISTORY_UPGRADE state; owner approves one scoped restart/backup. Never run the installer again, rotate credentials, or overwrite the live DB. Agent publication history remains managed separately in its existing tables.
