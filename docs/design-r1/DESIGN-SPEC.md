# CreatorPulse Studio — Workspace visual reference

**Version:** Reference R1 / proposed, 2026-11-25. **Acceptance:** owner delegated visual review and approved the reference as the implementation target. This is not V4 production and is not a connected TikTok application.

## How to review
Open `index.html` in a browser. The navigation and content filters use local sample data; no requests are made to CreatorPulse, TikTok, Hermes or Local Bridge. Resize the window to see responsive behavior. The Design preview control switches between illustrative connected/unlocked, locked and Bridge not configured states. All submission and approval actions are disabled; connection/setup actions are explanatory demos. No real credential should be entered.

The 1440 and 390 PNGs capture the initial viewport. The `-390-full` images are scrollable page illustrations with bottom navigation repositioned at the end for legibility. Screenshots do not represent the deployed app. Account names, handles, videos, metrics, queue state and observations are fictional fixtures. Username labels must be hidden or substituted with display names when the authorized API does not return usernames. Preview's model/provider wording is illustrative configuration, not telemetry.

## Visual tokens and layout
- Light neutral canvas `#f5f6f8`, white panels, border `#e5e8ed`, text `#172132`, secondary `#697586`, accent `#5145cd`, selected background `#efedff`. Semantic success `#167b57`, warning `#a45d12`; do not reuse success for unverified states.
- Desktop sidebar 224 px at full width, 190 px on intermediate screens; desktop top bar 64 px. Sidebar has workspace nav followed by connected accounts; account shortcuts filter Content without changing active session. Content canvas 30 px desktop gutters; modular 13–18 px panel gaps, 10 px radius. Title 27 px, body 14 px, table/body 12–13 px, captions 11 px. Use actual rendered prototype as reference; no need to preserve old layout.
- Mobile at <=768 px: independent layout, top bar 54 px, bottom nav 5 equal columns, 14 px content gutters (10 px at <=350 px), title 22 px (20 px at <=350 px). KPI 2×2, account rows and video rows instead of wide tables. Minimum 16 px input text; meaningful text should not be reduced below legibility. Touch targets target 44 px; refine minor icon actions at implementation. No horizontal scroll on main workspace.
- Brand icon/color, sample label, table text, numbers and styling are proposed choices, not pre-approved brand assets. Use accessible semantics, focus, labels and explicit empty/loading/error states in production.

## Modules
1. Overview: all-account aggregate followers, loaded video views, lifetime posts, review count only from verified unlocked operator data; account performance table/compact rows with relative loaded-view bars; actionable Needs attention; top content and recent publishing. Do not invent historical trend charts or daily deltas. Locked/unknown counts show dash (not 0), no inferred connection.
2. Accounts: directory with separate browser-session and agent-enrollment statuses, statistics, menu and content links. Add account disabled at capacity. Mobile compact account rows and metrics. Enrollment and browser session are independent; disconnect requires confirmation; true TikTok revocation remains separate.
3. Content: desktop data table with account column, date, views, likes, comments, shares. Mobile compact thumbnail list, search, account filter, sort, list/grid toggle. Pagination and details only from authorized data, no accidental account change. Actual cover images/URLs replace decorative fixtures.
4. Publishing: agent queue as primary surface, Review and History tabs, explicit target, source, mode, state, time. Agent records require operator authorization; manual history remains browser-local and should be labeled as such. Manual records may only display mode/status if known or verified; missing values show dash. Drafts needing human approval, approved records (subject to expiry), submissions and terminal state distinct; submitted is not published. Agent never approves itself. No fake unified durable manual draft queue.
5. AI Agent: operational status, verified Bridge connectivity, enrolled accounts, research evidence and settings. Setup secondary to operations when available; when not configured, clear setup guidance. Existing Hermes profile and model/provider/chat preserved. Configured flag alone must not become Connected. Operator key memory only, agent key restricted. Actual enrollment and diagnostic actions require authorization and host setup.
6. New post: explicit account first, then mode and media. Focused form and side preview desktop; mobile stacked. Inbox review requires verified HTTPS URL or supported MP4/MOV <=4 MB, human consent and completion in TikTok; Direct Post additionally requires real capabilities, duration, preview, explicit privacy, interaction and disclosure choices and consent. The prototype cannot verify media, makes no actual API call, and never enables submission. Agent Review modal illustrates the full authority boundary; actual review must retain all validation and policy links. No loss of draft data or account identity during target change.

## Acceptance gate
- Owner approves reference per screen, desktop and mobile, before implementation; visual acceptance remains open. If revised, update prototype, spec and screenshots together.
- Compare production-build fixture screenshots against reference at 320/390/430/768/1440 px; include empty/loading/error/partial/one-account/three-account, long names, setup/locked states, and account/consent integrity. The current reference has been rendered at all five sizes in its primary fixture; test coverage for production data/error and real service states remains to be built.
- Data availability is a release constraint: use actual API sources, add authorized diagnostics or aggregate reads when needed; never fake state. Existing browser scope, OAuth callbacks, persistent vault and human-only approval must remain intact. No production deployment before owner visual approval and full CI; verify the production alias/commit. No paid service or TikTok developer config changes.
- The original HTML reference is retained beside this specification; production implementation must use actual API data and maintain all safety boundaries.
